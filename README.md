# FocusProof

FocusProof is a personal learning accountability and analytics app for Windows. Ordinary study timers count a whole session as work. FocusProof instead estimates **Actual Learning Time (ALT)**: it uses local behavioural signals to judge how much of a session was spent working, and shows you why it reached that judgement.

> **ALT is an estimate.** It is built from behavioural signals (which app is in front, input activity, document changes, optional webcam presence). It shows how engaged you appeared to be. It does **not** measure whether learning took place.

FocusProof is a self-monitoring tool for your own use. It is not designed or intended for monitoring other people.

## Features

- **Assignments** with module, deadline, word targets, estimated hours, notes and monitored files/folders. Each one has its own analytics (ALT, sessions, productivity, time per 100 words, estimated remaining work, activity over time). You can archive an assignment without losing its history.
- **Study sessions** where you choose which signals to use. While a session runs, the screen is kept minimal: elapsed time, ALT, current state, and optional details.
- **Interval classification**: every few seconds the current interval is classified as Productive, Neutral, Distracted or Away. Each signal value, its weight and the reasons for the classification are stored.
- **Session reports** cover time, progress (words or lines added and removed, files changed, editing time), focus (longest productive block, distraction periods) and factual insights. They also include an interactive, colour-coded timeline. Click any block to see why it was classified that way.
- **History** and **Analytics**: time per day and per week, productivity and distraction trends, time by assignment, cumulative hours against net words, and productive time by hour of day.
- **Privacy page** with a separate toggle for each source and a "delete all data" option.
- **Crash-safe sessions**: every interval is saved as it happens. On the next launch, any unfinished session can be resumed, ended and recovered, or discarded.
- **Demo data** is generated by running the real engine over simulated activity. You can load or clear it from Settings.

## Getting started

Requirements: Windows 10/11, Node.js 22+ (tested with Node 24).

### Easiest: double-click `FocusProof.cmd`

The launcher installs dependencies on first run, rebuilds only when the source has changed, and then starts the app. You can also run it from a terminal:

```bash
npm run app          # same as double-clicking FocusProof.cmd
npm run shortcut     # adds a "FocusProof" shortcut to your desktop
```

To install it like a normal app (Start menu entry, no Node needed afterwards), run `npm run dist` and then run `release/FocusProof Setup <version>.exe`.

### Development

```bash
npm install          # also rebuilds better-sqlite3 for Electron and fetches the face model
npm run dev          # start with hot reload
```

`npm install` runs `postinstall`, which:
1. rebuilds `better-sqlite3` against Electron (`electron-builder install-app-deps`), and
2. runs `scripts/fetch-models.mjs`. This copies the MediaPipe WASM runtime into `src/renderer/public/mediapipe/` and downloads `face_landmarker.task` (~3.7 MB) into `resources/models/`. This is the only network access involved, and it happens at install time. If the download fails, the app still works with the webcam option disabled. Run `npm run fetch-models` later to retry.

## Architecture

```
src/
  shared/        Types, zod IPC schemas, IPC contract, default settings (used by every layer)
  main/          Electron main process: all monitoring, analysis and storage
    engine/        LearningTimeEngine interface, WeightedSignalEngine, pure summary functions
    monitoring/    ActivityMonitor (orchestrator), Win32ActivitySource, ActiveWindowMonitor,
                   InputActivityMonitor, screen/ (ScreenAnalyzer), focus/ (FocusAnalyzer),
                   documents/ (DocumentActivityAnalyzer, text metrics, .docx extraction)
    services/      SessionManager, ReportService, InsightService, AnalyticsService, DemoDataService
    db/            Connection, versioned migrations, repositories
    ipc/           Channel registration with zod validation and sender checks
  preload/       contextBridge APIs (main app and camera window), no business logic
  renderer/      React UI (app/) and the hidden camera worker page (camera/)
resources/win32/ PowerShell helper for foreground window and input activity
tests/           Vitest unit tests
```

### Data flow

```
Win32 helper ─┐
Screen thumb ─┤                 SignalFrame                   IntervalEvaluation
Camera (IPC) ─┼─► ActivityMonitor ──────────► LearningTimeEngine ──────────────► SessionManager ─► SQLite
File watcher ─┘   (hardware-free output)      (pure, swappable)                 (persist + live)  └► Renderer
```

- `LearningTimeEngine` consumes only `SignalFrame` objects. It never touches hardware, Electron or storage, so it is deterministic and unit-tested. To try a different algorithm, implement the interface and call `registerEngine()`. Each session and interval records the `engine_id` that produced it.
- `ScreenAnalyzer` is the extension point for OCR or a local vision-language model. `RuleBasedScreenAnalyzer` is the current implementation.
- `DocumentActivityAnalyzer` is the extension point for Word, Google Docs or Git integrations.
- The renderer talks to main only through one typed `invoke` bridge. Each channel is validated with zod, and only the main window may call it. The camera window has its own minimal bridge that can send derived numbers only.

### Electron security

`contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`, a strict CSP, and a custom `focusproof://` origin in production builds. Navigation and new windows are blocked. Camera permission is granted only to the hidden camera window, and only for video.

## Actual Learning Time

The analysis runs every *N* seconds (default 5). Each interval gets normalised signal scores from 0 to 1:

| Signal | Source | Default weight |
| --- | --- | --- |
| App/screen relevance | Foreground process and title rules, blended 60/40 with screen-content relevance | 30% |
| Input activity | Share of seconds with any input, plus a saturating input-rate curve | 20% |
| Document activity | 1 when a monitored file changed; decays over about 2 minutes | 25% |
| Webcam | presence × head-pose focus | 15% |
| Sustained context | Moving average of recent interval scores | 10% |

When a signal is **unavailable** (camera off, no files selected, helper unavailable), it is dropped and the remaining weights are renormalised. The app therefore works fully without the webcam.

Rule overlays then adjust the weighted score. Each overlay adds a readable reason:

- **Away**: idle for at least the away threshold (default 5 min), with no document change and no webcam presence. It also applies when the webcam reports you absent for that long.
- **Distracting app or site**: the score is capped below the neutral threshold.
- **Prolonged inactivity**: no input for at least the inactivity threshold (default 2 min) while no study material is in focus → distracted.
- **Reading grace**: study material in focus with little input is raised to at least Neutral, so short reading periods are not treated as inactivity.

The final score is classified as **Productive** (≥ 0.60), **Neutral** (≥ 0.35) or **Distracted**. All thresholds can be changed in Settings.

```
ALT = productive time + neutralContribution × neutral time      (neutralContribution default 0.5)
```

Distracted and away time never count. Time when monitoring wasn't running (the app was closed or the computer was asleep) is reported separately as *unmonitored* and excluded.

## Privacy model

Everything is local. FocusProof makes no network requests at runtime, and it has no telemetry and no cloud APIs.

| Source | Reads | Stores |
| --- | --- | --- |
| Webcam (off by default) | Frames in a hidden window, processed by local MediaPipe | Presence fraction and focus score only. No images or video, no identity recognition |
| Screen analysis | A 160×90 thumbnail held in memory | A visual-change number only. Nothing is written to disk |
| Active window | Foreground process name and title | Process name and a truncated title (titles can be turned off) |
| Input activity | Whether input occurred (`GetLastInputInfo`) | Counts and idle time. Never keys or text |
| Documents | Files you select | Path, size, word/line counts and deltas. Never contents |

## Limitations

- **Windows-first.** Active-window and input monitoring use a PowerShell helper that calls Win32 APIs. On other platforms the app falls back to OS idle time and has no window information.
- **Input activity** is sampled five times per second. Keyboard and mouse are told apart by whether the cursor moved, so a click without movement counts as "keyboard/other".
- **Screen relevance** is decided by rules on process names, window titles and keywords. Browser sites are recognised from tab titles only, and visible content isn't understood (no OCR yet).
- **Webcam focus** comes from head orientation, not eye gaze. Lighting, glasses or camera placement can affect it. With more than one monitor, calibrate in **Settings → Webcam calibration**: you look at the centre of each display (the app shows your Windows display layout), and the head angle for each is recorded. After that, looking at any calibrated screen counts as focused. Without calibration, only looking towards the camera counts.
- **`.docx` diffs** use extracted plain text, so formatting-only edits aren't counted. Word saves the file only on save or autosave.
- **Multiple displays.** Every display is captured and compared with its own previous frame, and the most active display drives the visual-change signal. Relevance still comes from the foreground window, whichever monitor it is on.
- ALT is a heuristic, and its default weights haven't been validated empirically.

## Future improvements

The architecture is designed so these can be added without a rewrite:

- Local OCR or a vision-language model behind `ScreenAnalyzer`
- Browser extension: send the exact URL or page category into `WindowObservation`
- VS Code, Word or Google Docs integrations, and Git/GitHub activity as extra document analyzers
- User-defined focus rules and a rule editor
- Personal machine-learning models as alternative `LearningTimeEngine`s, trained on stored signal history
- Deadline forecasting, calendar integration and automatic assignment detection
- Correlating productive time with assignment progress
